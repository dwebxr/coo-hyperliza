# Known Limits

The residual risks that were accepted, in one place. Each is described where its subject is; nothing in this list is enforced by code.

- **Start paths that skip Coo's defaults.** `elizaos start --character <file>` (and `dev --character`), and a start whose project fails to load, serve the web UI/API without Coo: no loopback default, no locked API, no `SENTRY_DSN=off`, no clean-up of stored secrets. Only the three lines in `.env` (`SERVER_HOST=127.0.0.1`, `ELIZA_SERVER_AUTH_TOKEN`, `SERVER_API_KEY`) and `SENTRY_DSN=off` protect such a start. With a token set, the API is as strong as that token: whoever has it can read and rewrite `.env`. Without a token, a request to the API can still have its body (up to 2 MB) parsed, and a malformed one logged as an error and reported to a Sentry DSN you set. ([Security](security.md))
- **The world's own origin is trusted completely.** Anything that can name a URL (the world, a script, an import request) can make the agent `GET` any path on the origin of `WS_URL`. Outbound requests under the policy do not go through a proxy, and nothing limits how often the agent fetches from a public host. ([What the Agent Downloads](downloads.md#what-this-does-not-do))
- **Voice (LiveKit) destinations.** Only the URL the world names is checked. LiveKit's native client resolves the name again itself, and the media connections it then makes (ICE, TURN) are not checked at all.
- **Sender ids on stock Hyperfy are forgeable.** Such a world passes on whatever sender id a client writes: keep `HYPERFY_SCENE_EDITS=off` there, and expect the per-sender chat limits to be sidestepped by changing ids. On a coo-world without `ADMIN_CODE` everyone is an admin. Operators listed in `HYPERFY_OPERATOR_IDS` are builders for Coo whatever the world thinks of them. ([Who Can Ask for What](authorization.md))
- **Scene edits are planned by the model** from the request, everyone's recent chat and the names of things in the world; the check is on who asked, not on what the plan says. Coo gets no confirmation from the world: "done" means changed locally and sent in a form the server's field policies take; Coo checks its own rank but not the world-wide budgets the server checks next (all blueprints together, the join snapshot's room).
- **Tips.** Coo verifies nothing on chain and thanks on the world's word. The public announcement names the recipient by display name, and names are not identities. ([Tips](tips.md))
- **Shop text.** The address recogniser is best-effort, with the list of what it does not recognise in [OpenPay Store Shop Clerk](shop.md); a seller can describe an address in a form it does not know. The agent's own replies are posted as the model wrote them and can contain an address.
- **Render page.** Chromium's memory can go over the limit by what the page allocates between two samples; a kill drops everything the page held; the circuit breaker is for the whole process, so kills caused by one world keep the render page down for the next connection too; a process that leaves Chromium's group and tree before it is sampled is not seen; while `ps` cannot be read only the deadlines apply. The offline arguments do not block WebRTC/UDP (nothing in the page uses it). ([What Bounds the Render Page](downloads.md#what-bounds-the-render-page))
- **Usage limits.** Counts are in memory and start from zero on a restart. `AI_MAX_TOKENS_PER_DAY` can be exceeded by what an image costs beyond the 5,000 tokens assumed for it. Speech-to-text another plugin asks for through the `TRANSCRIPTION` model is not metered. Scene-edit planning asks again after an error, as new calls under the limits. ([Cost Controls and Usage Limits](cost-controls.md))
- **World scripts (`sandboxed`).** No CPU or memory isolation: a script can hang or crash the agent, use everything the engine's script API offers, and send what it can read to any public https host. The error-event guard has the gaps listed in [World App Scripts](world-scripts.md). Use `off` for a world you do not trust.
- **Intake.** A frame larger than the limit has already been received when it is dropped. The number of entity lines in a prompt is not bounded. A world can keep the agent busy within the limits given in [What the World Can Make the Agent Take In](intake.md).
- **The OpenAI voice's fidelity check** compares the text with the model's own transcript of what it spoke, not with an independent transcription of the audio; audio that differs from its transcript would be played. The check is exact, so a correct reading written differently is not played and the reply goes to chat as text, after a request that may have been billed; decorative emoji (`😊` `✨` `👀` …) that end a sentence are left out of what it reads (the reply is then posted to chat as well), and what is to be spoken with any other emoji, a yes/no, choice or rating mark (`✅` `❌` `○` `☐` `★` …) or a `×` is not read by it at all. That the audio belongs to the answer asked for is checked only as far as the API's events name it. Only what is spoken is checked: at most the first 600 characters of a reply; a reply cut there is posted to chat as well, within the chat's four messages of 500 characters. (ElevenLabs, the main voice, has no such check, and a voice reply it speaks in full is not also posted to chat.) Its characters stay counted once the request was sent. ([Configuration](configuration.md#the-openai-voice))
- **PGLite** was checked to boot, not run in a world for any length of time.
- **Dependencies.** See [Dependency Advisories](development.md#dependency-advisories).
